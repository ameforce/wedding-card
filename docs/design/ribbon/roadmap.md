# 리본 제작 검증 순서

1. 메인 앱 실행과 프레임 요청을 지연한 첫 표시 실패를 재현한 뒤 초기 표지·정확한 인계·5초 준비 제한을 검증한다.
2. 저해상도 무채색 천에 재료 표식을 붙여 매듭 통과를 검증한다. 첫 형상부터 면이 교차하면 고친다. 같은 접근이 두 번 실패하면 매듭 통로와 접힘을 재설계한다.
3. 단독 동작이 통과한 뒤 새틴·그림자를 적용한다. 고정 프레임과 전체 하강 위치를 출력하고, 실제 화면 하단 퇴장과 측정된 종이 개방 경로를 연결한다. 종이는 양쪽 표지를 넘기는 회전으로 구현하며, 가장자리 경로뿐 아니라 무늬 압축과 좌우 명암 변화도 원본과 비교한다.
4. 요구 화면 너비와 긴 모바일 화면에서 첫 표시, 정상 재생, 준비·해석 실패, 건너뛰기, 새로고침, 화면 회전, 탭 복귀, 키보드와 동작 줄이기 설정을 검사한다. 프레임 순서뿐 아니라 중앙 틈의 본문 표시도 확인한다.
5. 리본 단독과 전체 개봉의 로컬 비교 화면을 제공하고 사용자의 iPhone Chrome 실기기 확인을 받는다. 승인 대상의 자산·재생 구성 해시를 고정한다.
6. 독립 검수와 필수 리뷰, 기존 테스트·빌드를 마친 뒤 승인된 결과만 보호된 GitHub Actions 배포로 전달한다. 운영 버전·자산·개봉 검증과 iPhone Chrome 재확인으로 마친다.

검증 전 단계는 완료로 간주하지 않는다. 단독 샘플이 실패하면 공개 인트로 연결과 배포를 진행하지 않는다.
