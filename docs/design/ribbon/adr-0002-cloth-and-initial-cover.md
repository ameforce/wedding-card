# 초기 표지와 천의 풀림 재제작

## 배경과 결정

사용자는 기존 오프닝의 늦은 리본 등장, 부자연스러운 풀림과 종이 개봉을 지적했다. 전체 프레임을 내려받은 뒤 처음 그리는 구조와, 고리 축소·직선화로 만든 동작이 원인이었다. 연속 프레임 재생 성공은 레퍼런스 재현의 증거가 아니다.

초기 HTML에 묶인 표지를 포함하고 앱 실행과 프레임 준비를 분리한다. 준비 상한은 표지가 보인 뒤 5초다. 첫 프레임을 그린 재생기에 같은 표시 주기에서 인계하며, 준비 실패나 건너뛰기로 끝난 표지는 뒤늦게 다시 시작하지 않는다. 기존 콘텐츠의 게시 리비전 결정과 사진을 보존한다.

리본은 한 장의 천을 기준으로 자유 끝단을 당기고, 자체 충돌과 종이 접촉을 계산한다. 기준 형상은 고정하고 고리와 매듭을 직접 축소하지 않는다. 저해상도 표식 실험에서 매듭 통과가 성립해야 재질 제작으로 넘어간다. 같은 접근에서 두 번 실패하면 통로·접힘을 재설계한다. 기존 형태 보간으로 조용히 대체하지 않는다.

매듭과 종이 연결부가 완전히 풀린 뒤에만 전체 하강 위치를 상대 변형과 분리한다. 화면에 필요한 추가 거리는 연출 보정으로 기록한다. 전체 리본이 실제 화면 아래로 16px 이상 나간 뒤에만 투명 종료 프레임을 그린다. 종이는 원본 영상에서 측정한 양쪽 경로와 명암 변화에 맞춰 연다.

사용자는 후속 확인에서 종이가 좌우로 밀리는 현재 표현을 지적하고 책장을 넘기듯 봉투를 벗기는 효과를 요청했다. 따라서 가장자리의 이동만으로 원본을 설명한 해석을 수정한다. 측정 곡선은 가장자리 위치 자료로 유지하되, 종이 면에는 바깥 접힘선을 축으로 하는 회전을 적용한다. 무늬의 가로 압축과 좌우 명암 차이를 함께 검증한다. 원본의 실제 3차원 형상을 복원했다고 간주하지 않으며, 초기 표지 인계와 리본 퇴장 후 개봉 순서는 보존한다.

## 내부 자산 계약

리본 매니페스트의 스키마 2는 첫 표지의 해시, 기준점, 완전 해제 프레임, 프레임별 하강 위치와 양쪽 종이 경로를 결속한다. 기본 해상도는 960×640, 초당 30프레임이다. 전체 시퀀스의 균일한 해상도 축소는 허용하되 개별 프레임 정규화는 금지한다. 압축 자산 4MiB, 관리하는 이미지 픽셀 버퍼 32MiB 예산을 지킨다.

기존 스키마 1 자산은 재제작 검증 중의 명시적인 과도기 자산이다. 이전 리본에 새 매니페스트를 붙여 물리 풀림이 검증됐다고 주장하지 않는다. 공개 API와 콘텐츠 스키마는 바꾸지 않는다.

## 사용자 확인과 배포

사용자는 리본 단독과 전체 개봉을 레퍼런스와 나란히 확인하는 방식을 선택했다. 확인 환경은 iPhone Chrome이다. 이 확인은 운영 배포 전 필수 단계이며, 구현 요청이 자동으로 확인을 대신하지 않는다.

기능 검증과 시각 판정은 분리한다. 승인된 자산과 재생 구성의 해시를 고정하고, 관련 시각 변경 뒤에는 다시 비교한다. 확인 후에만 보호된 배포 경로와 운영 검증을 진행한다. 실기기나 물리 풀림이 미검증인 동안에는 시각적 완료로 표시하지 않는다.

## 원본 측정

`scripts/ribbon/reference-paper-curve.json`은 사용자 영상의 해시와 프레임별 종이 가장자리 관찰값을 포함한다. 원본 픽셀은 공개 자산으로 배포하지 않는다. 원본에 있는 반복 프레임과 위치 도약을 그대로 재생하지 않도록, 관찰값에 양쪽별 단조 증가 곡선을 맞추고 오차를 기록한다.
